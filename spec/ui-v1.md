# chua 界面规格

**版本**：1.0.0
**状态**：初始版本。**框架无关部分**已定稿；渲染与控件实现方式待 ADR-0003（UI 框架选型）定稿后追加附录
**读者**：实现侧会话
**约束**：只描述"要什么"，不描述任何既有实现的"怎么写"。见 [`../CLEANROOM.md`](../CLEANROOM.md) §5。

---

## 0. 设计原则

1. **默认最少。** 打开软件第一眼只应该有：一个能粘贴链接的输入框、任务列表、总速度。
   分段、连接、日志、镜像源、限速细节——全部按需展开，不预占空间。
2. **每个像素都要有理由。** 任何装饰性元素必须回答"它帮用户做了什么决定"。答不上来就删。
3. **速度优先于观感。** 见 §8 的禁止清单——所有持续消耗 GPU 的装饰效果一律不做。
4. **状态永远可读。** 用户扫一眼列表就知道：哪些在跑、哪些卡了、卡在哪一步、下一步该做什么。
5. **不弹窗。** 除确认销毁性操作外，一切反馈就地呈现（行内状态、底部提示条）。

## 1. 窗口结构

单窗口，三段式：

```
┌───────────────────────────────────────────────────────────────┐
│  [ 粘贴链接或拖入文件 ]              [全部开始] [全部暂停] [+] │  顶栏
├───────────────────────────────────────────────────────────────┤
│  ▸ 文件名                        进度        速度      剩余    │  列表头
│  ─────────────────────────────────────────────────────────    │
│  ▸ report.pdf               ▓▓▓▓▓▓░░░░  2.1 MB/s   00:42      │
│  ▸ model.safetensors        ▓▓▓░░░░░░░  0 B/s      —   ⚠       │  任务列表
│  ▸ ubuntu.iso               ▓▓▓▓▓▓▓▓▓▓  11.4 MB/s  完成       │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│  3 个任务 · 总速度 13.5 MB/s · 限速关                     [详情]│  状态栏
└───────────────────────────────────────────────────────────────┘
```

- **顶栏**：唯一的输入入口。粘贴即建任务；拖入 URL 文本或 `.torrent` 文件同样建任务。
- **列表**：唯一的常驻主体。
- **状态栏**：一行汇总。放不下时优先保留总速度与活动任务数。
- **详情**：从右侧滑出的抽屉，默认关闭，宽度不超过窗口的 40%。

**单窗口**是硬要求。MUST NOT 出现多窗口管理、标签页、浮层设置窗口。

## 2. 任务列表

### 2.1 默认列

| 列 | 内容 | 说明 |
|---|---|---|
| 文件名 | 图标 + 名称 | **主列，占据剩余宽度**。名称过长时中间省略，保留扩展名 |
| 进度 | 细进度条 + 百分比 | 进度条是**行的背景条**还是独立列，由 ADR-0003 决定；两者都满足本规格 |
| 速度 | 当前速率 | 无活动时显示 `—`，不显示 `0 B/s` |
| 剩余 | 预计剩余时间 | 无法估计时显示 `—`，MUST NOT 显示跳动的数字 |
| 状态徽标 | 仅在异常时出现 | 完成 / 暂停不显示徽标（进度本身就是信息），只有警告与失败显示 |

**简约的含义**：默认 5 列。大小、来源数、保存目录、创建时间等一律进详情，
由用户在列设置里按需打开（见 §6.3）。

### 2.2 行高与密度

- 提供「舒适 / 紧凑」两档，默认**舒适**。
- 舒适档行高应能容纳两行文字（文件名 + 状态副行）；紧凑档单行。
- 切换密度 MUST NOT 引起列表重建或滚动位置丢失。

### 2.3 异常行的表达

失败与警告 MUST 直接显示**可执行的下一步**，而不是错误码：

```
▸ model.safetensors   ▓▓▓░░░░░░░  —  ⚠ 服务器限制了来源，可换一个镜像重试   [换源]
```

- 文字长度限制在一行内；放不下时截断，完整说明进详情。
- 有明确动作的异常 MUST 提供就地按钮（换源 / 重试 / 打开目录）。
- **错误码本身只在详情里出现**——主界面给结论与动作。

### 2.4 列表行为

- 必须虚拟化：MUST 支持 5 万行而不损失滚动帧率（§8）。
- 排序：默认按创建时间倒序；支持按文件名 / 大小 / 进度 / 速度排序。
- 排序切换 MUST NOT 打断进行中的任务。
- 分组：默认**不分组**。按状态分组是可选的开关，默认关。

## 3. 交互

### 3.1 主流程（粘贴即下载）

1. 用户粘贴 URL 到顶栏输入框 → 立即创建任务并开始，**不弹新建对话框**。
2. 需要用户补充信息时（目标目录冲突、需要选择 BT 文件、需要鉴权），
   在**该行内**展开一个内联面板，不弹窗。
3. 需要用户决策但用户不在时（例如自动任务遇到冲突），任务停在明确的等待状态，
   并在状态栏提示，MUST NOT 阻塞其他任务。

### 3.2 键盘

| 键 | 动作 |
|---|---|
| `Ctrl+V`（窗口内任意位置） | 把剪贴板内容当作新建任务的输入 |
| `Space` | 暂停 / 继续选中任务 |
| `Delete` | 删除选中任务（需确认；有未完成数据时确认文案说明后果） |
| `Enter` | 打开选中任务的文件 |
| `Ctrl+A` | 全选 |
| `Esc` | 关闭详情抽屉 / 取消内联面板 |

### 3.3 鼠标

- 双击行：打开文件（未完成时打开所在目录）。
- 右键：上下文菜单，按状态裁剪可用项。**未知状态一律不提供可执行项**。
- 拖拽：仅允许对「排队中」的任务调整顺序；拖拽 MUST NOT 改变正在下载任务的行为。

### 3.4 完成后的行为

完成后 MUST NOT 弹任何东西。可选行为（打开文件 / 打开目录 / 通知）由用户在设置里开启，默认关。

## 4. 任务详情

抽屉，四个分区，默认停在「常规」：

| 分区 | 内容 | 何时可见 |
|---|---|---|
| **常规** | 名称、大小、保存路径、创建/完成时间、校验值、来源构成 | 始终 |
| **分段** | 分段的区间、进度、绑定来源 | 有多分段时 |
| **连接** | 当前连接数、每来源的实时速率、重试计数 | 下载中 |
| **日志** | 该任务的事件流水 | 始终（默认折叠） |

**来源构成**（常规页）：用一条横向堆叠条展示各来源贡献的字节占比，附文字说明。
这是本产品与普通下载器的主要差异点，必须在详情里可见，但**不得**出现在主列表。

## 5. 设置

- **分类树 + 右侧内容**的两栏布局。分类不超过 7 个，子项不超过 3 层。
- 设置项顺序 MUST 稳定：用户升级后不得因为新增设置项而找不到原来的位置。
- 每个设置项 MUST 有：名称、一句说明（描述**影响**而不是复述名称）、控件。
- 需要重启或重载才生效的项 MUST 就地标注。

分类（固定顺序）：

1. **下载**——默认目录、并发任务数、单任务分段数、分段粒度、断点持久化周期
2. **速度**——全局限速、单任务限速、低速自动降速（可选）
3. **协议**——BT 端口与做种策略、磁力处理、FTP/SFTP 选项
4. **网络**——代理（HTTP / SOCKS5 / PAC）、系统代理发现、超时与重试
5. **镜像与加速**——镜像规则库开关、规则来源、单一来源降级策略
6. **界面**——密度、主题、语言、完成后的行为
7. **高级**——数据目录、日志级别、导入导出配置

## 6. 视觉

### 6.1 主题

- 提供 浅色 / 深色 / 跟随系统。默认跟随系统。
- 颜色以语义命名（背景 / 表面 / 边框 / 主文字 / 次文字 / 强调 / 警告 / 危险），
  MUST NOT 在界面代码里出现字面色值。
- 强调色只用于**一个**地方：当前活动元素。全部界面里强调色的出现面积应小于 5%。

### 6.2 字体与中文

- 优先使用系统界面字体；MUST 有完整的中文字体回退链。
- **硬要求**：中文界面下无缺字、无豆腐块、无基线跳动；中英文混排时数字与拉丁字母
  不出现异常间距。
- 中文字号不应小于 12px（等价度量）；行高不小于字号的 1.5 倍。
- 数字（速度、大小、时间）SHOULD 使用等宽数字，避免刷新时宽度跳动导致整行抖动。

### 6.3 图标

- 单色矢量图标，两档尺寸（行内 / 工具栏）。
- 图标 MUST NOT 承担唯一的信息载体：每个图标都要有文字或提示。

---

## 7. 文案

- 全部面向用户的文案走**共享词条表**，MUST NOT 在界面代码里硬编码中文。
- 词条表 MUST 有 en + zh 两份，键集合一致，并有自动漂移守卫（CI 检查）。
- 失败提示的写法：**发生了什么 + 现在该做什么**。
  - ✅ `服务器限制了来源，可换一个镜像重试`
  - ❌ `错误 403`
  - ❌ `下载失败`

---

## 8. 性能预算与禁止事项

### 8.1 预算（与 `../.omp/PLAN.md` §3 一致，此处定义测量方法）

| 指标 | 预算 | 测量方法 |
|---|---|---|
| 冷启动到首帧 | < 300 ms（目标 150 ms） | Windows + SSD，清除文件缓存后计时到首帧提交；取 5 次中位数 |
| 空闲 CPU | < 0.1% | 无任务、窗口最小化、静默 5 分钟的平均值 |
| 空闲内存 | < 80 MB | 同上时点的常驻内存 |
| 5 万行滚动 | 稳定 60 fps | 5 万条记录，滚轮连续滚动 10 秒，记录最长帧时间 |
| 进度刷新 | 10 Hz 不重排 | 20 个活跃任务，观察是否出现整列表重排 / 闪烁 |
| 滚动中单帧 CPU | < 4 ms | release 构建，同上场景 |
| 内存（1000 任务 / 20 活跃） | < 200 MB | 稳定运行 10 分钟后 |

### 8.2 禁止事项

以下全部**禁止**，因为它们直接违反"速度优先"：

1. 毛玻璃 / 背景模糊 / 实时阴影等需要每帧重算的合成效果
2. 常驻动画（呼吸灯、渐变流动、无限旋转）
3. 进度条之外的任何按帧变化的装饰
4. 内嵌浏览器内核作为界面载体
5. 每次数据更新重建整个列表或整个详情面板
6. 在主线程做文件系统扫描或哈希计算
7. 空闲时的周期性磁盘扫描或数据库写入（会唤醒机械盘）
8. 滚动时同步做文本整形 / 布局测量（必须有测量缓存）

### 8.3 允许的动效

只允许**状态变化**的短动效，时长 ≤ 150 ms，且 MUST NOT 阻塞输入：
抽屉滑出、行内面板展开、状态徽标出现。滚动、进度更新 MUST NOT 有动效。
