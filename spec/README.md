# spec/ —— 行为规格

本目录是**实现侧的唯一信息来源**。

## 规则

1. **谁写**：由接触过 copyleft 上游源码的会话（规格侧）编写。实现侧**不得**修改本目录。
2. **写什么**：行为、接口语义、约束、边界条件、错误分类、性能目标。**不写**代码，
   不写任何与对方源码逐行可对应的类型 / 函数 / 模块结构。判据见 `../CLEANROOM.md` §5。
3. **版本**：每个规格文件头部标注版本号。任何实质修改都要升版本号，并在文件的变更记录里写一行。
4. **实现侧发现缺口时**：不改规格，在 `../.omp/TODO.md` 的「待规格侧回答」一节记一条，
   由规格侧更新后按新版本继续（`../AGENTS.md` §4.5）。

## 为什么规格可以写

版权保护的是**表达**，不是**思想**。算法、协议、功能需求、架构模式、性能目标都是思想，
任何人都可以自由使用。干净室流程要保证的只是：**写代码的人没有看过对方的源码**。
规格就是隔离这两件事的界面——它记录"要什么"，不记录"对方怎么写的"。
