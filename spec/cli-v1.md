# chua CLI 行为规格

**版本**：1.0.0
**状态**：初始版本
**读者**：实现侧会话
**约束**：只描述"要什么"。见 [`../CLEANROOM.md`](../CLEANROOM.md) §5。

---

## 0. 这个 CLI 是什么，不是什么

**是**：M1 的**验证宿主**。它的存在意义是让引擎可以被端到端驱动 ——
`spec/acceptance/run.py` 就是通过它把引擎当作黑盒验证的。

**不是**：面向用户的产品界面。那个是 M5 的 GPUI 桌面端。

因此这里刻意从简：不做参数美化、不做交互式提示、不做配置向导。
但它必须**足够稳定**，因为验收套件依赖它的命令行形状与退出码。

## 1. 硬约束

- CLI **不得**依赖任何 UI / 窗口框架。
- 它是**宿主**，所以它拥有面向用户的文案；引擎只上报结构化原因
  （`spec/engine-v1.md` §8.4）。CLI 把 `Failure` 翻译成一行可读文字。
- CLI 不得在引擎里新增任何供它专用的钩子。只使用引擎的公开接口。

## 2. 命令

### `add <url> [dest] [--detach] [--segments N] [--limit <速率>]`

创建一个任务并开始下载。

- `dest` 省略时，由引擎推导文件名并落到默认目录。
- **默认阻塞**：前台运行直到任务进入终态（`Completed` / `Failed`），然后按 §3 退出。
- `--detach`：登记任务后立即返回（退出码 0），不等结果。
- `--segments N`：覆盖该任务的分段数上限。
- `--limit`：该任务的限速（如 `2M`、`500K`、`0` = 不限）。
- 若 `dest` 已存在，**必须**按 `spec/engine-v1.md` §7.4 上报冲突并由命令行决定行为；
  M1 的行为固定为：**报错退出，不覆盖**。（产品化的"询问用户"留给 M5。）

### `list`

列出所有任务。每行一个任务，至少包含：`id`、状态、进度、`dest`。
**必须可以在任务下载中调用**（即读状态不阻塞传输）。

### `status <id>`

单个任务的详情，包含分段数与各段进度。

### `pause <id>` / `resume <id>` / `remove <id>`

对应引擎的三个操作。`remove` 在任务有未完成数据时**必须**要求 `--force`。

### `resume --all`

把持久化存储里所有非终态任务恢复。**这是验收套件的续传检查所依赖的命令。**

语义要求：
- 恢复后，原先处于 `Downloading` 的任务必须回到 `Queued` 并重新开始传输
  （`spec/engine-v1.md` §7.3(2)）。
- **已经落盘的字节不得重下**。这是续传的全部意义，也是验收套件 `resume-after-kill`
  检查实际测的东西。

## 3. 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功（`add` 阻塞模式下 = 任务完成） |
| `1` | 用法错误（未知子命令、参数非法） |
| `2` | 任务失败（引擎上报了 `Failure`） |
| `3` | 任务不存在 |
| `4` | 目标文件冲突（`dest` 已存在且未指定覆盖） |

**退出码是验收套件与 CI 的判据，必须区分"用法错误"与"任务失败"。**
把两者都归成 `1` 会让自动化无法判断到底哪里出了问题。

## 4. 输出

- 人类可读文本，**不是** JSON（M1 不需要机器接口；需要时再加 `--json`，届时升规格版本）。
- 进度输出**不得**以高于 10 Hz 的频率刷新（`spec/engine-v1.md` §9.4 的理由同样适用：
  终端刷屏既无信息量又浪费 CPU）。
- 非 TTY 时**不得**输出进度条或 ANSI 控制字符 —— 验收套件会捕获输出，
  控制字符只会污染日志。

## 5. 状态存放

- 引擎的持久化存储位置由 CLI 决定，**默认放在用户数据目录下**，
  并且可以由环境变量覆盖（验收套件需要让每个场景用干净的状态目录）。
- 环境变量名：`CHUA_DATA_DIR`。验收套件在运行前设置它。

## 6. 验收套件依赖的契约（改动即破坏验收）

`spec/acceptance/run.py` 目前依赖以下四点。改这四点必须同回合改套件：

1. `add <url> <dest>` 阻塞到终态，成功退出 0、失败退出非 0。
2. `add` 在 `dest` 已存在时报错退出而不覆盖。
3. `resume --all` 能续上被 `kill` 打断的任务。
4. `CHUA_DATA_DIR` 能隔离状态目录。
