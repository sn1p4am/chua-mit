# chua 产品方案

> 本文件是产品与技术的总纲。具体决策见 `DECISIONS.md`，排期见 `ROADMAP.md`，进度见 `PROGRESS.md`。

---

## 1. 定位

**面向中国大陆网络环境的极速多协议下载器。**

目标用户是"需要从境外站点稳定拿到大文件"的中文用户：开发者（模型权重、包、依赖）、
内容创作者（素材、素材包）、以及长期使用 IDM / 迅雷类工具、对交互效率敏感的重度用户。

要解决的三个具体问题：

1. **拉不动**——境外源在国内经常限速、丢包、被签名 URL 与限流策略卡住。
2. **说不清**——失败了只给一个错误码，用户不知道下一步该做什么。
3. **太慢**——软件本身启动慢、界面卡、常驻占资源，比下载还烦。

## 2. 范围

### 做

- 多协议：HTTP/HTTPS、BitTorrent（含磁力）、HLS/DASH、FTP/FTPS、SFTP
- 多源聚合：同一文件的多个镜像源分段并行下载
- 分段并发、断点续传、智能限速、崩溃恢复
- 中国大陆网络优化：镜像规则、签名 URL 与限流场景的处置、代理与 PAC
- 中文排障：把失败翻译成"发生了什么 + 现在该做什么"
- 浏览器嗅探（扩展），把页面上的下载交给本机引擎
- 托盘常驻、剪贴板监听、文件关联

### 不做

- 不做网页视频解析下载（不解析页面提取流媒体）——这是另一个产品
- 不做云盘客户端、不做播放器、不做 BT 做种农场
- 不做账号体系与云同步（M6 之前不碰）
- 不做移动端（架构上不留死角，但不排期）

## 3. 性能预算（硬指标）

**这些不是"优化目标"，是验收项。任一项超标即视为该里程碑未完成。**

| 指标 | 预算 | 测量条件 | 里程碑 |
|---|---|---|---|
| 冷启动到首帧绘制 | **< 300 ms**（目标 150 ms） | Windows，SSD，首次启动（非热缓存） | M5 |
| 空闲 CPU（托盘常驻，无任务） | **< 0.1%** | 稳定 5 分钟平均值，窗口最小化 | M5 |
| 空闲内存（托盘常驻，无任务） | **< 80 MB** | 同上 | M5 |
| 任务列表滚动（5 万行） | **稳定 60 fps，无掉帧** | 鼠标滚轮连续滚动 10 秒，记录最长帧 | M5 |
| 实时进度刷新 | **10 Hz 更新不引起重排** | 20 个活跃任务同时刷新 | M5 |
| 单帧 CPU 时间（滚动中） | **< 4 ms** | release 构建 | M5 |
| 内存（1000 个任务，20 个活跃） | **< 200 MB** | 稳定运行 10 分钟后 | M5 |
| 安装包体积 | **< 30 MB** | Windows x64 安装包 | M6 |
| 下载吞吐 | 单任务跑满链路带宽 | 本地 range server，8 段并发 | M1 |

> 下载吞吐是引擎的指标，其余是宿主的指标。引擎的指标在 M1 建立基线，此后不允许回退。

## 4. 技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| 语言 | Rust（Edition 2024） | 内存安全 + 单二进制 + 无运行时 |
| 异步运行时 | `tokio` | 生态标准，MIT |
| HTTP | `reqwest` / `hyper` | MIT OR Apache-2.0 |
| TLS | `rustls` | Apache-2.0 OR ISC OR MIT；避免 OpenSSL 的部署麻烦 |
| BitTorrent | `librqbit`（Apache-2.0） | 含 DHT / peer / tracker / UPnP / LSD，是最大的成本节约点 |
| HLS / DASH | `m3u8-rs` / `dash-mpd`（MIT） | 解析；解密与拼装自研 |
| FTP | `suppaftp`（MIT OR Apache-2.0） | — |
| eD2K | **自研**（按公开协议文档） | 无现成宽松实现 |
| 持久化 | SQLite（`rusqlite`） | 单文件、可嵌入式、MIT |
| UI | **待定**（ADR-0003） | 见下 |
| 依赖白名单 | 见 ADR-0005 | 全部宽松许可 |

**UI 候选与判据**：首要候选是 Zed 的 GPUI 及其性能分支 `gpui-fast`（均 Apache-2.0）。
关键判据是四项速度指标、**中文字体回退与输入法可靠性**、Windows 图形后端、以及 1–2 年周期内的
版本稳定性。调研结论落 ADR-0003。

## 5. 架构草案（M1 定稿，见 ADR-0004）

```
┌──────────────┐  事件   ┌──────────────────┐
│  宿主        │ ◄────── │                  │
│  桌面 UI     │         │   chua-engine    │
│  CLI         │ ──────► │   零 UI 依赖     │
│  （未来移动）│  请求   │   零 FFI 依赖    │
└──────────────┘         └──────────────────┘
                                  │
                          ┌───────┴────────┐
                          │  协议实现层     │
                          │  http/bt/hls/… │
                          └────────────────┘
```

不变式：

1. 引擎不依赖任何 UI 或 FFI 框架——这是它能被无图形环境的集成测试覆盖的前提。
2. 引擎不直接写用户界面文案；失败原因以**结构化枚举**上报，由宿主翻译成中文。
3. 所有对外长驻状态（任务、分段进度、配置）都在引擎侧持久化，宿主可以随时重启。

## 6. 与既有工具的差异

| | 本产品要做的 |
|---|---|
| 通用下载器 | 中国大陆网络优化是一等功能，不是插件 |
| 纯命令行工具 | 默认图形界面，且界面本身要快 |
| 只报错误码的工具 | 失败必须给出"发生了什么 + 现在该做什么" |
| 单源下载 | 同一文件的多镜像源分段聚合 |

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| UI 框架不成熟（ADR-0003 未决） | 可能返工 | 引擎与 UI 解耦（ADR-0004），UI 可替换 |
| 中文输入法 / 字体在候选框架上不可靠 | 目标市场不可用 | 选型阶段就用中文界面 + 中文输入做实测 |
| eD2K 需自研 | 工期 | 排在 M2 末尾，可独立延期 |
| 干净室流程降低实现效率 | 工期 | 规格写得足够细；接受这个代价（ADR-0006） |
| 同类开源产品 fork 本产品闭源商用 | 商业 | MIT 是非独占授权，可同时走 open core；护城河放服务端 |
