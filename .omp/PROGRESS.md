## 规格自查记录

### `spec/engine-v1.md` v1.0.0 — 通过

按 `CLEANROOM.md` §5 逐条检查：

| 检查项 | 结论 |
|---|---|
| 是否包含任何既有实现的具体类型 / 函数 / 模块名 | 未包含。全部使用本规格自定的领域词（任务 / 来源 / 分段 / 探测 / 快照），并在 §0 明确要求实现侧遇到命名撞车时改名 |
| 是否包含可逐行对应的结构设计 | 未包含。§3.2 给的是**状态迁移合法性表**（行为约束），不是状态机的代码结构 |
| 是否复制了任何文案 / 词条 | 未复制。§8.4 明确要求引擎只上报结构化原因、由宿主翻译文案 |
| 是否描述了"对方怎么写的" | 未描述。§5 只规定**判定需要哪些证据**（长度必须配强验证器），未规定用什么数据结构承载 |
| 是否包含代码 | 无代码块以外的任何代码 |

**边界说明**：§5.2 的证据组合表来自规格侧对"跨源一致性"这一**功能需求**的独立表述。
它规定的是"什么算同一文件"这一判定标准（思想），不是承载它的表达。实现侧从未接触上游源码，
因此按本规格产出的代码不存在表达层的复制路径。

### `spec/ui-v1.md` v1.0.0 — 通过

| 检查项 | 结论 |
|---|---|
| 是否包含任何既有实现的类型 / 函数 / 模块名 | 未包含。界面规格全部用布局与交互语言描述，不含任何控件类名或框架 API |
| 是否包含可逐行对应的结构设计 | 未包含。§2.1 的列定义是**信息需求**，§5 的分类是**设置项归属**，都不绑定实现结构 |
| 是否复制了任何文案 / 词条 | 未复制。§7 明确要求文案走共享词条表且禁止硬编码；文中出现的中文示例句为本规格自行撰写 |
| 是否描述了"对方怎么写的" | 未描述。§8.2 的禁止事项来自本项目自己的性能预算推导，不是对既有实现的转述 |
| 是否包含代码 | 无 |

**边界说明**：本规格刻意**不**规定控件类型、布局引擎、渲染方式——这些留给 ADR-0003。
这样即使 UI 框架选型变化，规格也不需要重写。
